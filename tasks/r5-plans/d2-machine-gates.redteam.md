## 2. Findings

### F1（P0）G1 `--compare` 判定未区分 tier，与本计划自己的「measure 起步」机制自相矛盾

- **问题**：§3.2 判定写「**对每个规则**，`new_rate > old_rate + tolerance` 且 `new_count > old_count` → 回归；**旧基线无此规则且新跑 count>0 → 回归**」，而同节开头定义「人类语料上 **screen** 规则的任何命中=误报」。两句话合读有二义：若按字面适用全部 42 条，则 §2.5 的扩展规则（L01b/c/d **从 measure 起步**）与任何在人类语料有命中的 measure 条目（L01c「表面上…其实」叙事高频、L04 提示性冒号、M03-06 单字虚词在人类语料**必然大量命中**——RESEARCH 实测「就」6.45/千字、「很」「了」更高）一落表即触发 exit 1，而它们已在最低 tier、无处可降，只能撤回——「measure 起步」机制死锁。若只拦 screen，判定逻辑又没有写。
- **证据**：计划 §2.5 vs §3.2 判定文本；RESEARCH.md:116-117（虚词人类侧 6.45/3.87 每千字）。
- **处置**：compare 判定显式分层——tier=screen：rate/count 回归 → exit 1；tier=measure：只输出 diff 报告不拦（或加 `--strict-measure` 显式开关）；「新增规则 count>0 → 回归」限定为「新增 **screen** 规则误报>0」。同时把「误报=screen 规则在人类语料**叙述层**（对话抑制后）的命中」写进 G1 定义（现状 §3.2 那句无「叙述层」限定，掩码会静默收窄误报定义，见 F2）。

### F2（P1）「母本语料无对话故金丝雀基线不受影响」——前提错位：金丝雀不是母本语料

- **问题**：§3.1.4 的口径偏差声明以「母本语料无对话」论证「金丝雀基线不受影响」，把母本语料（lieflat 329 篇论述文）与 R0 金丝雀（选自 nwriter `kb_corpus` 的**女频短篇网文**）混为一谈。R5 总计划风险清单第一条自己写着「金丝雀是女频短篇，项目是男频长篇」。金丝雀有大量对话 → ①叙述层分母 ≠ 全文分母，金丝雀基线数字与母本锚点（0.70/千字等，全文口径）**不可直接对照**；②对话掩码 + ≥50% 抑制会滤掉金丝雀引号内命中，screen 误报测量系统性偏低 → G1 门比设计意图更松。
- **证据**：计划 §3.1.4 vs `tasks/R5-knowledge-absorption.md:201`（金丝雀女频短篇）、`:44`（金丝雀源=kb_corpus）；RESEARCH.md:33（母本人类语料=公开论述文章）。
- **处置**：①修正声明：金丝雀对话密集，分母口径偏差对金丝雀**同样生效**，母本锚点对照须标注「全文口径 vs 叙述层口径」不可比；②基线 `corpus` 记 `dialogue_ratio`（stats 已有该字段，纳入基线并呈报用户）；③G1 的「误报」定义按 F1 补「对话抑制后的叙述层命中」限定——这一定义本身可辩护（与正文预筛同口径自洽），但必须显式声明而不是靠掩码静默实现。

### F3（P1）BASELINE「不是…而是」的「别名→L01 覆盖」不成立，锚点口径漂移

- **问题**：§2.4 称母本 `(不是\|并非)[^，。]{1,20}(，\|)而是` 语义被 L01 覆盖。实际两正则**交叉包含**：BASELINE 的 `[^，。]` 不排除 `！？` 与 `\n`（可跨句跨行匹配），L01 的 `[^，。！？\n]` 更严；BASELINE 只认「而是」，L01 另有「不在于/而在于」分支。四组反例：`不是A？而是B`（BASELINE 命中、L01 不命中）、`不是A\n而是B`（同前）、`不在于A，而是B`（L01 命中、BASELINE 不命中）、`不是A，而在于B`（同前）。且 RESEARCH 的锚点数字「不是…而是 0.70/千字」出自 **BASELINE 口径**——按别名去重后，L01 的金丝雀测量与该锚点对照口径不一致。
- **证据**：check-translationese.py:42 vs compare-human-ai.py:17 两正则逐字比对；RESEARCH.md:222（0.70/千字锚点）。
- **处置**：二选一：①独立建 B02（measure，逐字移植 BASELINE 正则），规则账目改 43 条并同步 §2.1 计数与 rule_table_hash 初值；②保留别名但在 §8 对方向1 显式声明「L01≠BASELINE 口径，0.70 锚点不可与 L01 金丝雀 rate 直接对照」。推荐 ①（测量条目零成本，锚点可比性值回一条规则位）。

### F4（P1）L07b（的…的…的连用）直发 screen，违反本计划自己的升降级纪律，且母本有跨顿号误报前科

- **问题**：§2.5 规定「扩展规则一律从 measure 起步，金丝雀误报为 0 且方向1 出判据文本后才可升 screen」——这条纪律只写给表 D，而 L07b 作为**源规则 tier 升格**（母本 MARKERS 是测量条目，SKILL 10.1 触发标记）被直接定为 screen，未走任何验证流程。同时该正则有母本明载的误报史：排除类不含顿号，偏正并列「X的A、Y的B、Z的C」（RESEARCH 原例：「巴西的LGPD、印度的DPDPA」）必命中——这正是叙事文（器物罗列、外貌描写、人物群像）的高频正常结构。女频金丝雀上大概率误报>0。
- **证据**：RESEARCH.md:250（失误 #3）；计划 §2.4 L07b 行 vs §2.5 纪律。
- **处置**：L07b 首发 measure，R0 基线零误报后按升降级流程升 screen；或改正则为排除顿号（`[^，。、]`）——但那是改口径，须在 rule_table_hash 与锚点对照声明里记录。若坚持首发 screen，必须在计划里写明豁免理由并接受「步骤 4 基线一出即可能触发降级」的返工。

### F5（P1）密度分母偏差的**方向**未向方向1 声明：对话密集章被系统性放大读数

- **问题**：§3.1.4 只声明了「分母含对话会把密度稀释 ~1/3 不可比」（选择叙述层分母的理由），未声明该选择的推论：AI 味句式主要发生在叙述层（对话天然口语化、命中被 suppress 滤掉，分子几乎不缩），而分母随对话占比缩 30-70%——同一阈值下**对话密集章（女频）density 读数系统性偏高、叙述密集章（男频）与锚点可比**。这不是「女频漏报」而是「女频过度检测」；反向地，「对话内命中一律豁免」本身是口径选择（对话里的翻案腔不检），对话密集章的这一半漏检也无指标。D1 若把 craft 卡阈值写成全局「每千字 ≤N」，跨频道/跨章节横向判级必然错判体裁。
- **证据**：§3.1.4 声明原文只有单侧；§8 对方向1 接口无 density×dialogue_ratio 关系说明。
- **处置**：§8 对方向1 补三条：①density 单位为「每千**叙述**汉字」，跨章比较时 `dialogue_ratio` 是混杂变量，阈值判级须按频道/对话占比分层或声明适用范围；②「对话内命中不检」是有意豁免，deny 率与误报率统计均基于叙述层；③母本锚点倍率的分母是全文汉字（论述文≈叙述层），仅近似适用于叙述密集章。

### F6（P1）对话过滤的假阴性无任何监控指标——「多掩=少误报」只对 G1 一侧成立

- **问题**：三处掩码放大器可造成大面积叙述漏检：①段内未闭合开引号掩到段尾（跨段续引的网文体例下，首段从引号起整段全掩）；②直引号 `"` 奇数个时翻转开关把段尾全掩；③嵌套错序（「『」』）时按家族弹错栈。G1 只约束假阳性、G2 管引文、G3 管 deny 率——**假阴性没有任何门**；`stats.dialogue_ratio>0.6` 是全文级 advisory，单段 50% 掩码不触发。掩码正确性完全依赖「引号体例规范」这一未验证假设（女频短篇直角/弯引号混排史未知）。
- **证据**：§3.1.2 掩码规则 + §7 风险表第一行（「多掩=少报，方向安全」——只对 G1 安全，对 screen 召回不安全）。
- **处置**：stats 增加 `unclosed_quote_spans`（未闭合计数）与 `max_para_mask_ratio`（段级最大掩码率）两个 advisory 指标进输出与基线；测试 E/F 之外补跨段续引端到端用例（首段开引号未闭 → 该段句层规则全漏检的计数断言，把「漏检多少」变成可断言数字而非沉默行为）。

### F7（P2）G2 对「零 findings 回执」无防线

- **问题**：空 findings 数组（schema 合法）+ verdict=approved 的「什么都没查」回执是纸面化重灾区，verify 会直接 PASS（summary 全 0）。计划判定逻辑只遍历 findings。
- **处置**：`findings_total===0 && verdict==='approved'` → 至少 ADVISORY（`--strict` 下 FATAL）；或在接线文本注明该形态由主控人工把关。

### F8（P2）G2 只验「引文存在」不验「引文相关」——绕过路径未声明

- **问题**：reviewer 可从草稿任意位置抄一句真话作无关 finding 的 excerpt，机器必判 hit。归一化（全半角/引号折叠/删空白）还进一步扩大误命中面（6 字以上常用串随处可见）。这是 G2 的已知边界，但计划未声明，后续 G5/账本会误以为「exit 0 = 证据为真」。
- **处置**：§3.3 或 §5 G2 行补边界声明：G2 验证的是证据**存在性与版本绑定**，相关性（引文是否支撑论点）仍归主控/红方抽查；weak_excerpt 阈值 6 考虑升到 8 并在报告里附命中次数（多处命中=证据力弱）。

### F9（P2）canary 工程口径三缺口：per-file 聚合未写明、语料指纹不校验、tolerance 跨单位

- **问题**：①母本句层规则在 join 全文上跑（`[^，。]` 可跨 `\n` 跨篇）、段层 per-file（每篇段序独立，`i==0` 每篇重置）——D2 若把语料 join 成单 text，P03 的「非首段」会把第二篇首段算进去、P01 滑窗跨篇接续，段层口径全错；计划 §3.2 只写「每规则汇总」未写 per-file。②`--compare` 不校验 `corpus.files`/`han_chars_total` 与旧基线一致，语料增删后 rate 对比静默失效。③`tolerance` 是单一数值，但 rate_unit 有 per_1k_han/para_100/pct 三种，同一数值跨单位意义不同。
- **处置**：实现规格写明「句层可 join（忠实母本）、段层必须 per-file（每篇独立分段、非首段每篇重置）」；compare 启动时校验语料指纹（files 数 + han_chars_total，不一致 → 警告或要求 `--allow-corpus-drift`）；tolerance 按 rate_unit 归一或仅对 per_1k_han 生效并注明。

### F10（P2）deny 率采集的工程细节：LIKE 只数行不数条、note 通道语义二义、修订轮 prescreen 脱钩

- **问题**：①`findings_json LIKE '%fpr-deny:%'` 数的是**回执行数**，deny 率公式需要**条数**——条数级统计实际依赖 `json_each`（node:sqlite 内置 SQLite 含 JSON1，可用，但计划没写）；②deny 落 `severity:'note'`，与真问题 note 混在同一档，「note 总数」指标对 D5 失真，D5 须按 `code LIKE 'fpr-deny:%'` 过滤——该过滤条件未在 §8 对方向5 声明；③novel-writing SKILL step 6 的 UPDATE（修订）分支不写 metadata_json，修订轮草稿的新 prescreen 摘要与章节版本脱钩，deny 率分母（`prescreen.screen_counts`）可能指向上一版草稿的候选数。
