## 2. 层级重校建议(U1 裁决核心)

基线实证:**「零容忍 screen」语义只对 3 条规则成立**(L06 0.005 / L11 0.005 / P02 0),其余 screen 规则在人类小说叙述层均有稳定或间歇命中——它们在论述文语料上是人类侧≈0 的判别特征,在**叙事文体**里是人类正常写法。

| 方案 | 内容 | 后果 |
|---|---|---|
| A(建议) | **重分层**:screen 仅保留 L06/L11/P02(+观察 L09/L10 一轮);L01/L02/L03/L07a/L08/P01/P03 转 measure——其判级改由 craft 卡**章节阈值**承担(阈值+频率判级本来就是卡的能力,如 L03 走 hardrules「同段≤1/全章≤5」、L01 走「≤2 次/章」) | 预筛候选不再零容忍误伤人类写法;G1 门对 screen 层仍然零容忍可执行 |
| B | 维持现分层,screen 命中仅作低权重候选(判级靠审查) | G1 的「screen 误报>0 即回归」对 7 条规则永远触发,门失去判别力,实际不可运行 |
| C | screen 语义改「超阈值命中才入候选」(阈值=卡面阈值折算) | 语义最贴卡,但把阈值判断移进脚本,违背「脚本不判级」边界 |

方案 A 与「脚本不判级」红线兼容:脚本报事实,tier 只决定候选是否注入;判级语义在卡与审查。L03 的 hardrules 阈值(全章 ≤5)对照人类基线 0.92/千字≈2.8 次/3000 字章,余量 ~1.8×,暂不动,标「临时锚点(金丝雀校准中)」。
