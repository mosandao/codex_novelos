# 爽点与连载反馈

先识别目标读者等待的具体兑现，再设计铺垫、受压、反制、兑现和新代价。爽点必须改变地位、资源、关系、认知或行动空间，不能只靠围观者惊叹。

开篇或转折可使用反常现象、身份反差、冲突前置、信息差或倒计时，但只展示足够产生问题的部分，不立即解释全部底牌。章节末应留下具体未完成问题，而不是空泛预告。

反馈频率根据当前卷的压力曲线和题材调整，不套固定章数公式。输出读者期待、兑现节点、代价和下一层问题。

## 关联方法

- **story-expectation-design**：本方法定义**反馈频率与爽点结构**（战术节奏层）；全书**承诺结构与兑现节点**的架构层设计见 story-expectation-design。两者互补——先用 story-expectation-design 定全书承诺骨架，再用本方法填充每卷/每章的反馈节奏。本书为非爽文/纯文学题材时，本方法不适用。
