# 人物契约

**主要人物全量设计**：主角、核心对手、主锚点、卷级关键载体——凡架构移交清单点名需要人物承载的职责，全部在本契约立档，不只设计主角。**次要角色不在本契约**：卷级配角由卷纲「卷级配角班底」（volume_outline 的 `volume_characters`）生成，章级一次性或短弧配角由章纲执行卡「本章新登场人物微档案」预登记（规划端造人，正文只消费不发明），锁定/接受后落人物注册表；需要升级为卷级常驻或跨卷回归时走 change proposal 出本契约新 revision。

每个立档人物定义：初始状态、欲望与恐惧、核心执念（主角专属）、误判、能力边界与知识边界、必须付出的代价、心理运作简表、人物弧状态变化、关键关系张力、退场设计（含计划内死亡）。逐项说明如何服务 Architecture 与 Strategy。

主角除"欲望与恐惧"外，必须定义一个**核心执念**——一个超越本能求生、专属于"这个人"的私人驱动力：为什么偏要在这具处境里活下来？核心执念驱动主角所有行为，让选择成为"他只能这么做"而非"作者需要他这么做"。缺乏核心执念的主角只是优秀的求生机器，读者无法理解他为何非赢不可。

好坏对照（核心执念）：坏——「他想变强，因为想保护重要的人」（任何主角都成立，无私人性）；好——「他要赢回母亲被宗族除名的那块牌位——不是原谅她，是让宗族亲手把牌位请回去」（只属于这个人的执念，换一个人即不成立）。

主角不可全篇保持"冷静分析"的稳定态。必须在设计中预留**失稳空间**，至少包含以下之一：判断失误、情绪失控、欲望压过理智、被迫付出代价的抉择。让主角像一个正在经历事情的人，而非作者的计算器；让读者看到他失控、犯错、付出代价的瞬间。

好坏对照（失稳空间）：坏——「他在压力下会更坚定」（无失稳，只是形容词升级）；好——「他在被人叫对已死父亲的旧称时会失神三秒——这三秒里他做过一次错误判断，代价要到第二卷才显形」（可写的失效点 + 延迟代价）。

## 上游消费：作者内核怎么用（kernel 层，注入时生效）

`kernel_full` 的心理运作八维是**作者的观察方式，不是角色模板**——它决定「这些人物被怎样看」，不决定人物长什么样：

- 角色可以拥有与作者内核不同的需求、盲点、知识边界和价值选择；**全员同构于内核八维** = 作者内核覆盖角色，审查判 blocking。
- 每个立档人物的**心理运作简表**从八维中选 3-4 个对该人物最要命的维度，写成精简五段（倾向/触发/常见反应/可能盲点/可修正方向）——维度选择要能解释该人物的核心选择与失稳点，不是八维全抄。反临床标签纪律同内核层：只写可观察倾向，禁诊断语域。
- 作者 `kernel_blindspots.overlooks` 是叙述的目光缺口（由 Writer 侧处理），不是角色的缺陷清单；角色的盲点按角色自己的经验长。
- 无内核注入（旧项目占位节）时，心理简表直接从人物经历反推，跳过本节。

## 每人心理运作简表与知识边界

- **心理简表**（3-4 维五段式）：写进每个人物档案。例：「防御补偿：用资格证明掩盖出身焦虑——触发：被问师承；反应：抢着接最险的活；盲点：把善意的援手读成施舍；修正：被同级用实力而非资历折服后松动」。
- **知识边界**（有限知识）：每个立档人物声明他知道什么、不知道什么、以为什么（错的）。人物的知识来自其位置与经历，**不自动继承作者的知识生态**；跨学科知识只进作者分析层，不变成角色台词。

## 围绕 central_contradiction 的立场矩阵

围绕 `book_soul.central_contradiction` 为主要人物分配相互冲突、各有事实依据且各自需要付出代价的答案。至少一个有能力、有合理动机的人物必须能反驳主角或作者偏爱的立场；不得让所有人物共享同一结论、沦为作者扩音器。`protected_dignity` 保护人物不被叙事羞辱，但不免除行为后果。

不要重写全书战略。与世界资源或规则有关的假设必须显式列出，供 Character/World 交叉审查。

## 架构移交清单消费（逐项认领，缺项即 blocking）

Architecture 移交清单中的人物侧条目必须在人物契约中逐项落地——每个载体在 roster 里有名有档：

1. **施压螺旋的人物载体**：每条压力螺旋由哪个人物具象承载（压力从人身上来，不从旁白来）。
2. **对手自洽账簿**：核心对手有自己的胜利路径与代价账——他也在按自己的最优解行动，不是等主角升级的木桩。账簿含：他要什么、他愿意付什么、他对主角的认知如何更新。
3. **行为残迹预埋清单**：人物的过去以可观察的行为残迹入场（伤、习惯、忌口、随身物），不是简历式背景陈述——每个残迹标注「何时被剧情消费」。
4. **回归面孔名单**：会二次登场的人物（卷级回收）登记，避免一次性工具人堆积。

## 死亡设计（计划内死亡才写）

推动剧情的重要人物死亡是一次**不可逆的剧情状态变化**，不是「怎么死」的桥段。凡计划内死亡（含远期），在人物档案内附**死亡设计卡**：

- **必要性**：不死主线还成立吗？失踪/背叛/残废/流放/昏迷能否产生同等效果？死亡带来哪些不可替代的后果？回答不了 = 改用退场，不杀。
- **因果链**：长期背景原因 → 角色自己的选择 → 他人的选择 → 制度或环境压力 → 直接冲突 → 死亡方式。「害怕 X 却死于 X」不能只当反差噱头——要能回答他为何无法逃避、这是否来自选择或制度。
- **最后选择**：死前是否拥有最后的主体选择（拒绝、托付、揭露、原谅）——纯被动死亡只承担激发主角功能 = 工具人化。
- **死亡影响追踪**：得知死亡 → 短期反应 → 中期行为改变 → 长期价值/关系/目标改变；对主线、阵营、道德债、主题各推一层。
- **性别风险**：女性角色死亡不得只承担激发男主/制造道德债/美化牺牲的功能——与男性角色同等参加因果链与最后选择。

## 退场设计（每个立档人物必答）

长篇中人物减戏正常，但因果不能凭空消失。每个人物档案必答**退场设计**：

- **预期退场状态**（七型选一或组合）：`完成型`（阶段目标完成主动离开）/ `迁移型`（前往其他地区组织战场）/ `转化型`（从行动者变为制度/导师/幕后支持者）/ `关系型`（因价值观或道德债与主角分道）/ `功能转移型`（职责被人物/组织/制度接替——注明谁接）/ `休眠型`（暂无戏份，保留状态与回归条件）/ `死亡型`（走死亡设计卡）。
- **退场三问**：此人的债务、承诺、秘密如何处理？退场是否其自主选择？退场后还如何影响主角与世界（遗产、口碑、未结之账）？
- **回归条件**：休眠型与迁移型必须写明什么条件下回归（谁去请、什么事触发）。

## 条件语法模块（按项目组装）

频道轴的人物层落地（男频对手账簿与力量兑现载体 / 女频道德债权账户与选择性道德 / 全向双轴立场）**不在本主干**——组装器按 setup 取值附加，索引见 `modules/manifest.json`。

## 检查点决策点产出

产出 candidate 时，在 metadata 的 `decision_points` 字段附上 2~4 个关键决策点的爽点选择题。决策点是"错了会崩盘"的命门（如主角核心性格底色、主角与核心对手的关系基调、主角驱动力来源、重要人物的死亡时点），不是所有细节。每个决策点含：

- `question`：给用户的问题（如"主角的核心性格底色"）。
- `options`：3~4 个选项，每个含 `label`、`detail`、`tradeoff`。
- `source_excerpt`：candidate 里对应片段，供追溯。

decision_points 附在 metadata 由主控呈现给用户裁决；用户选择经主控融合进修订 candidate。对本书无关的决策点可省略，不得凑数。

## character_roster 结构化出口

metadata 另附 `character_roster` 数组（schema 见 `config/schemas/planning-candidate.schema.json`）——每个立档人物一行：`name` / `role_class`（main|secondary）/ `arc_role`（主角|核心对手|主锚点|卷级载体等一句话职责）/ `登场卷` / `预期退场`（七型之一或「持续活跃」）。契约锁定时由 `scripts/novelos_register_characters.py` 落人物注册表（characters 表）；卷级配角经卷纲班底、章级新配角经执行卡微档案登记为 secondary/minor，与本 roster 合流。

## 文档结构约定

人物契约的正文必须按下列二级标题结构组织，便于投影按人物拆分检索：

- **每个人物**（含同类多人，如多名棋手）各占一个二级标题，格式固定为 `## 人物档案：{角色类型}｜{名字}`，主角放在第一个。
  - 角色类型用简短标签：`主角` / `主锚点` / `旧神` / `棋手` / `对手` / `同行` 等。多人同类型时每人独立一节，**不要**合并到一个 `##` 下再用 `###` 分。
  - 示例：`## 人物档案：主角｜塞维尔`、`## 人物档案：主锚点｜伊诺`、`## 人物档案：棋手｜渡脉者`、`## 人物档案：棋手｜余烬记录者`。
- 该人物的全部字段（初始状态、欲望与恐惧、核心执念、误判、能力与知识边界、心理简表、必须付出的代价、人物弧、关系张力、失稳设计、退场设计、死亡设计卡[如有]）写在其 `## 人物档案` 节内，可用 `###` 子标题组织。
- **跨人物内容**——人物设计总则、kernel 消费声明、central_contradiction 立场矩阵、Character 对 World 的假设、童年线碎片呼应、人物清单与职责校验、检查点决策点、上游一致性自检——放在人物档案节**之外**的独立 `##` 章节。

投影渲染（`scripts/novelos_render_projection.py`）按「人物档案」标题把契约拆成 `规划/人物契约/00-总览.md`（跨人物内容）加每人物一份文件；主角序号 `01`，其余按出现顺序。识别不到该结构的契约会退化为单文件并告警，因此务必遵守上述标题格式。

## 交付前自检

1. **全量覆盖**：移交清单的每个载体在 roster 有名有档；主要人物（主角+核心对手+主锚点+卷级关键载体）全部立档。
2. **核心执念**：私人性成立（换一个人即不成立），好坏对照的自检标准已过。
3. **失稳空间**：至少一处可写的失效点 + 其代价（含延迟代价）。
4. **心理简表**：每人 3-4 维五段齐全；无临床语域；未全员同构内核八维。
5. **知识边界**：每人声明知道/不知道/以为错；无角色继承作者知识生态。
6. **立场矩阵**：主要人物对 central_contradiction 各有代价的答案，至少一人能反驳主角立场。
7. **移交消费**：施压螺旋载体 / 对手自洽账簿 / 行为残迹 / 回归面孔四项齐。
8. **死亡设计**：每张死亡卡过了必要性四问 + 最后选择 + 影响追踪；无工具人化死亡（含性别风险检查）。
9. **退场设计**：每人七型之一 + 退场三问；休眠/迁移型带回归条件。
10. **边界**：无无战略职责人物；World 假设已显式列出；未重写战略；次要角色未混入本契约。
11. **形式**：文档结构符合「人物档案」标题约定；metadata 含 decision_points（或省略声明）与 character_roster。
