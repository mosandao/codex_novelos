# 人物契约

**主要人物全量设计**：主角、核心对手、主锚点、卷级关键载体——凡架构移交清单点名需要人物承载的职责，全部在本契约立档，不只设计主角。**次要角色不在本契约**：卷级配角由卷纲「卷级配角班底」（volume_outline 的 `volume_characters`）生成，章级一次性或短弧配角由章纲执行卡「本章新登场人物微档案」预登记（规划端造人，正文只消费不发明），锁定/接受后落人物注册表；需要升级为卷级常驻或跨卷回归时走 change proposal 出本契约新 revision。

每个立档人物定义：初始状态、欲望与恐惧、价值排序（主角与核心对手）、核心执念（主角专属）、误判、能力边界与知识边界、必须付出的代价、心理运作简表、人物弧状态变化、关键关系张力、退场设计（含计划内死亡）。逐项说明如何服务 Architecture 与 Strategy。

主角除"欲望与恐惧"外，必须定义一个**核心执念**——一个超越本能求生、专属于"这个人"的私人驱动力：为什么偏要在这具处境里活下来？核心执念驱动主角所有行为，让选择成为"他只能这么做"而非"作者需要他这么做"。缺乏核心执念的主角只是优秀的求生机器，读者无法理解他为何非赢不可。

好坏对照（核心执念）：坏——「他想变强，因为想保护重要的人」（任何主角都成立，无私人性）；好——「他要赢回母亲被宗族除名的那块牌位——不是原谅她，是让宗族亲手把牌位请回去」（只属于这个人的执念，换一个人即不成立）。

主角不可全篇保持"冷静分析"的稳定态。必须在设计中预留**失稳空间**，至少包含以下之一：判断失误、情绪失控、欲望压过理智、被迫付出代价的抉择。让主角像一个正在经历事情的人，而非作者的计算器；让读者看到他失控、犯错、付出代价的瞬间。

好坏对照（失稳空间）：坏——「他在压力下会更坚定」（无失稳，只是形容词升级）；好——「他在被人叫对已死父亲的旧称时会失神三秒——这三秒里他做过一次错误判断，代价要到第二卷才显形」（可写的失效点 + 延迟代价）。

## 世界移交清单消费（席位认领，缺项即 blocking）

`world_contract`（含 metadata）已锁定，其结构化产物在人物层逐一认领：

1. **席位认领**：world 岗位表（`metadata.seats`）的每个主要席位逐一处置——本契约认领（该人物 roster 行带 `seat_ref` 回指席位名）/ 移交卷级班底（正文标注）/ 维持虚位（沿用 world 侧标注）。主要席位无人认领且无处置 = blocking；roster 引用不存在的席位名 = blocking。
2. **能力边界对世界细则**：每人能力上限与成长代价对 world 的力量体系细则（境界门槛/代价机制/不可逆阈值）立档，不得只对 architecture 粗法则——细则级冲突（人物进阶速度越过 world 门槛）= blocking。
3. **语域分化**：人物台词语域按其出身组织与教育取词（world 术语语域表的分层用法）——仙门弟子与市井人物不得同腔说话；缺分化 = warning。
4. **六角色对应**：人物在重要规则里的角色（执行者/受益者/豁免者/破坏者）与其立场动机一致——执行者不执行、受益者反规则，必须有人物层的理由（不是剧情需要）。
5. **代价承担者认领**：strategy costs 落 `plot_character` 的不可逆代价，认领到具体人物的「必须付出的代价」；world `dimension_costs` 的不可逆档默认由配角/世界/物品承担——本阶段不得给主角新增永久代价。
6. **席位与退场**：「功能转移型」退场注明席位由谁重坐（world 岗位的可移交性在此兑现）。

## persona 怎么用（分身层，persona_full 注入时生效）

分身是本书的作者签名，人物设计必须与它对表——四个用法：

- **盲区 → 角色类型门**：分身 `cannot_write` 是硬边界。核心立档人物（主角/核心对手/主锚点）不得整档生活在盲区场景里（分身写不了纯恶角色，核心对手就不能设计成纯纯的恶）——确需涉盲区的角色，档案内标注绕开方式（侧写/借他人之口/转喻/留白），全知叙述假装在场 = persona 未生效。
- **目光 → 失稳/执念的观察频段**：失稳点与核心执念的呈现落在分身擅写的情绪频段（分身目光偏冷峻克制，执念就别设计成只能靠嚎啕大哭呈现的形态）。
- **库存 → 细节原料**：行为残迹、童年线碎片呼应、忌口随身物这些细节从分身与内核的素材库存取材，正文标注来源（`persona_part: XX`）——无来源的细节是编的，编的细节不耐磨。
- **有限视角 → 知识边界的叙述预留**：主角「以为错的」清单要与分身的 POV 契约兼容——分身擅写内心 OS 时误判可以直写，擅写外部观察时误判要靠行为显形。

无绑定（旧项目）跳过本节，细节从人物处境直接长。

## 上游消费：作者内核怎么用（kernel 层，注入时生效）

`kernel_full` 的心理运作八维是**作者的观察方式，不是角色模板**——它决定「这些人物被怎样看」，不决定人物长什么样：

- 角色可以拥有与作者内核不同的需求、盲点、知识边界和价值选择；**全员同构于内核八维** = 作者内核覆盖角色，审查判 blocking。
- 每个立档人物的**心理运作简表**从八维中选 3-4 个对该人物最要命的维度，写成精简五段（倾向/触发/常见反应/可能盲点/可修正方向）——维度选择要能解释该人物的核心选择与失稳点，不是八维全抄。反临床标签纪律同内核层：只写可观察倾向，禁诊断语域。
- 作者 `kernel_blindspots.overlooks` 是叙述的目光缺口（由 Writer 侧处理），不是角色的缺陷清单；角色的盲点按角色自己的经验长。
- 无内核注入（旧项目占位节）时，心理简表直接从人物经历反推，跳过本节。

## 每人心理运作简表与知识边界

- **心理简表**（3-4 维五段式）：写进每个人物档案。例：「防御补偿：用资格证明掩盖出身焦虑——触发：被问师承；反应：抢着接最险的活；盲点：把善意的援手读成施舍；修正：被同级用实力而非资历折服后松动」。
- **知识边界**（有限知识）：每个立档人物声明他知道什么、不知道什么、以为什么（错的）。人物的知识来自其位置与经历，**不自动继承作者的知识生态**；跨学科知识只进作者分析层，不变成角色台词。

## 围绕 central_contradiction 的立场矩阵

围绕 `book_soul.central_contradiction` 为主要人物分配相互冲突、各有事实依据且各自需要付出代价的答案。至少一个有能力、有合理动机的人物必须能反驳主角或作者偏爱的立场；不得让所有人物共享同一结论、沦为作者扩音器。`protected_dignity` 保护人物不被叙事羞辱，但不免除行为后果。

不要重写全书战略。与世界资源或规则相关的引用以已锁定的 world_contract 为准——发现世界层缺口（人物必需的制度/机制 world 没建）走 change proposal 回 world 出新 revision，不在本契约隐式发明世界设定。

## 价值排序与反事实测试（主角与核心对手必做）

「他最看重家族」没有预测力——压力下死守什么、让出什么才有。为主要人物（至少主角与核心对手）用**反事实取舍**逼出价值排序：给他两样都真想要的东西，强制弃一，看弃哪样。

- **取舍题**：每人 2~3 组二选一（如「保宗门名声 vs 保妹妹性命」「复仇得手 vs 真相公开」）——选项必须都是他真想要的，弃掉不想要的东西不构成测试。
- **链式排序**：结果写成一句话链（如 `传承 > 复仇 > 名声 > 性命`），存于「欲望与恐惧」之后；链首是死守，链尾是可让。
- **排序解释既有设计**：失稳点应触发在链首受威胁处；立场矩阵里他实际付出的代价应落在链尾。排序解释不了的行为 = 人物模型没立住——回去改设计，不许改排序硬圆。
- **言行落差归位**：声明的欲望在链首、实际却总为链尾牺牲的——要么是设计矛盾（改），要么升格为可写的自欺，写进「误判」字段；两不沾 = 纸面排序。
- **修订轮比对基线**：新 revision 翻转链首两位 = 人物换核，走 decision point 报用户裁决，不得静默翻转。

## 架构移交清单消费（逐项认领，缺项即 blocking）

Architecture 移交清单中的人物侧条目必须在人物契约中逐项落地——每个载体在 roster 里有名有档：

1. **施压螺旋的人物载体**：每条压力螺旋由哪个人物具象承载（压力从人身上来，不从旁白来）。
2. **对手自洽账簿**：核心对手有自己的胜利路径与代价账——他也在按自己的最优解行动，不是等主角升级的木桩。账簿含：他要什么、他愿意付什么、他对主角的认知如何更新。
3. **行为残迹预埋清单**：人物的过去以可观察的行为残迹入场（伤、习惯、忌口、随身物），不是简历式背景陈述——每个残迹标注「何时被剧情消费」。
4. **回归面孔名单**：会二次登场的人物（卷级回收）登记，避免一次性工具人堆积。

## 死亡设计（计划内死亡才写）

推动剧情的重要人物死亡是一次**不可逆的剧情状态变化**，不是「怎么死」的桥段。凡计划内死亡（含远期），在人物档案内附**死亡设计卡**：

- **必要性**：不死主线还成立吗？失踪/背叛/残废/流放/昏迷能否产生同等效果？死亡带来哪些不可替代的后果？回答不了 = 改用退场，不杀。
- **因果链**：长期背景原因 → 角色自己的选择 → 他人的选择 → 制度或环境压力 → 直接冲突 → 死亡方式。「害怕 X 却死于 X」不能只当反差噱头——要能回答他为何无法逃避、这是否来自选择或制度。
- **最后选择**：死前是否拥有最后的主体选择（拒绝、托付、揭露、原谅）——纯被动死亡只承担激发主角功能 = 工具人化。
- **死亡影响追踪**：得知死亡 → 短期反应 → 中期行为改变 → 长期价值/关系/目标改变；对主线、阵营、道德债、主题各推一层。
- **性别风险**：女性角色死亡不得只承担激发男主/制造道德债/美化牺牲的功能——与男性角色同等参加因果链与最后选择。

## 退场设计（每个立档人物必答）

长篇中人物减戏正常，但因果不能凭空消失。每个人物档案必答**退场设计**：

- **预期退场状态**（七型选一或组合）：`完成型`（阶段目标完成主动离开）/ `迁移型`（前往其他地区组织战场）/ `转化型`（从行动者变为制度/导师/幕后支持者）/ `关系型`（因价值观或道德债与主角分道）/ `功能转移型`（职责被人物/组织/制度接替——注明谁接、席位由谁重坐）/ `休眠型`（暂无戏份，保留状态与回归条件）/ `死亡型`（走死亡设计卡）。
- **退场三问**：此人的债务、承诺、秘密如何处理？退场是否其自主选择？退场后还如何影响主角与世界（遗产、口碑、未结之账）？
- **评价轨迹**（主要人物必答）：此人身后世界怎么议论他——当时评价与身后评价可以不同甚至反转（生前被视为逆臣、身后被追认改革先声），评价落差本身是人物的一部分。评价出自世界内立场（政敌/门生/民间/史笔），不是作者旁白盖棺定论；反转须有世界内可见的依据（信息公开、制度后果显形、受益者掌笔），并服务 central_contradiction 的终局回答——不得借反转替作者翻案或说教。
- **回归条件**：休眠型与迁移型必须写明什么条件下回归（谁去请、什么事触发）。

## 条件语法模块（按项目组装）

频道轴的人物层落地（男频对手账簿与力量兑现载体 / 女频道德债权账户与选择性道德 / 全向双轴立场）与题材人物光谱（genre_profile 非空时）**不在本主干**——组装器按 setup 取值附加，索引见 `modules/manifest.json`。

## 检查点决策点产出

产出 candidate 时，在 metadata 的 `decision_points` 字段附上 2~4 个关键决策点的爽点选择题。决策点是"错了会崩盘"的命门（如主角核心性格底色、主角与核心对手的关系基调、主角驱动力来源、重要人物的死亡时点），不是所有细节。每个决策点含：

- `question`：给用户的问题（如"主角的核心性格底色"）。
- `options`：3~4 个选项，每个含 `label`、`detail`、`tradeoff`。
- `source_excerpt`：candidate 里对应片段，供追溯。

decision_points 附在 metadata 由主控呈现给用户裁决；用户选择经主控融合进修订 candidate。对本书无关的决策点可省略，不得凑数。

## character_roster 结构化出口

metadata 另附 `character_roster` 数组（schema 见 `config/schemas/planning-candidate.schema.json`，交付前自查：roster 结构符合 planning-candidate.schema.json、规模档位与席位指认自检；机器校验门未覆盖）——每个立档人物一行：`name` / `role_class`（main|secondary）/ `arc_role`（主角|核心对手|主锚点|卷级载体等一句话职责）/ `登场卷` / `预期退场`（七型之一或「持续活跃」）/ `seat_ref`（可选，认领的 world 席位名）/ `essence`（**人物卡一句话要点，main 必填**——执念/失稳点/语域口癖/最要命的关系，≤160 字，正文执行端经 character_essence 槽消费，写作与审校都看得到）。

**essence 写法**：它不是 arc_role 的重复——arc_role 说「他在故事里干什么」，essence 说「写他时必须抓住什么」。好——「对被除名母亲的牌位执念（谈宗族即失措，三秒失误第二卷显形）｜仙门雅言，避市井俚语」；坏——「聪明冷静的主角」（无失效点、无语域，等于没写）。没有 essence 的人物卡是空的：契约设计得再好，Writer 看不见就等于没设计。

**roster 规模 × scale 档位区间**（validate 机器门）：短篇 2-5 / 中篇 3-8 / 长篇 5-12 / 超长篇 8-16——立档人物数（不含班底/微档案）超出区间即缺陷；区间不足由卷级班底补员，超出说明人物契约越权吸食了班底职责。

契约锁定时由主控经插件 novelos_register_characters 门工具落人物注册表（characters 表）；卷级配角经卷纲班底、章级新配角经执行卡微档案登记为 secondary/minor，与本 roster 合流。

## 文档结构约定

人物契约的正文必须按下列二级标题结构组织：

- **每个人物**（含同类多人，如多名棋手）各占一个二级标题，格式固定为 `## 人物档案：{角色类型}｜{名字}`，主角放在第一个。
  - 角色类型用简短标签：`主角` / `主锚点` / `旧神` / `棋手` / `对手` / `同行` 等。多人同类型时每人独立一节，**不要**合并到一个 `##` 下再用 `###` 分。
  - 示例：`## 人物档案：主角｜塞维尔`、`## 人物档案：主锚点｜伊诺`、`## 人物档案：棋手｜渡脉者`、`## 人物档案：棋手｜余烬记录者`。
  - 该人物的全部字段（初始状态、欲望与恐惧、价值排序[主角与核心对手]、核心执念、误判、能力与知识边界、心理简表、必须付出的代价、人物弧、关系张力、失稳设计、退场设计、死亡设计卡[如有]、席位认领[如有]）写在其 `## 人物档案` 节内，可用 `###` 子标题组织。
- **跨人物内容**——人物设计总则、kernel/persona 消费声明、central_contradiction 立场矩阵、strategy 移交认领总表（弧职责/承诺认领/代价认领）、席位认领总表、童年线碎片呼应、人物清单与职责校验、检查点决策点、上游一致性自检——放在人物档案节**之外**的独立 `##` 章节。

## 交付前自检

1. **全量覆盖**：移交清单（架构四项 + strategy 弧职责）的每个载体在 roster 有名有档；主要人物全部立档。
2. **席位认领**：world 主要席位逐一处置；roster seat_ref 全部回指存在的席位；能力边界对 world 细则立档。
3. **strategy 挂接**：character_arcs 逐条有载体；midstory/terminal 承诺有认领人；弧与阶段骨架无冲突。
4. **persona 门**：核心人物不整档落分身盲区（涉盲区者带绕开方式）；细节原料标注来源；失稳/执念落在分身擅写频段。
5. **核心执念**：私人性成立（换一个人即不成立），好坏对照的自检标准已过。
6. **失稳空间**：至少一处可写的失效点 + 其代价（含延迟代价）。
7. **价值排序**：主角与核心对手各有 2~3 组反事实取舍题与链式排序；失稳点落在链首受威胁处、立场代价落在链尾；言行落差已归位（改设计或升格误判），无纸面排序。
8. **心理简表**：每人 3-4 维五段齐全；无临床语域；未全员同构内核八维。
9. **知识边界**：每人声明知道/不知道/以为错；无角色继承作者知识生态。
10. **立场矩阵**：主要人物对 central_contradiction 各有代价的答案，至少一人能反驳主角立场。
11. **死亡设计**：每张死亡卡过了必要性四问 + 最后选择 + 影响追踪；无工具人化死亡（含性别风险检查）。
12. **退场设计**：每人七型之一 + 退场三问；休眠/迁移型带回归条件；功能转移型带席位重坐；主要人物评价轨迹已设计（世界内立场出评价，反转有依据）。
13. **边界**：无无战略职责人物；未重写战略；未隐式发明世界设定（缺口走 change proposal）；次要角色未混入本契约。
14. **规模档位**：roster 数在 scale 区间内、无重名、main 在场——机器门待 R4 JS 化。
15. **人物卡**：main 人物 essence 齐全且非 arc_role 复述（含执念/失稳/语域至少其二）；「待契约认领」席位全部有人认领。
16. **形式**：文档结构符合「人物档案」标题约定；metadata 含 decision_points（或省略声明）与 character_roster。
