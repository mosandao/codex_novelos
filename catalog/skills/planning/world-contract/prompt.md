# 世界契约

只实现 Architecture 与 Strategy 实际需要的势力、制度、资源、地点和规则。每项设定必须说明叙事用途、约束对象、代价、可被利用的边界和与其他规则的关系。

世界只能提供承载 `book_soul` 冲突的条件和后果，不能让宇宙法则、系统奖励或设定说明自动证明作者偏爱的立场正确。对立答案都必须有真实资源、制度激励和生存压力作为支撑。

不要生成无叙事消费者的百科设定，不要改写规则来源。涉及人物能力或关系的假设必须显式列出，供 Character/World 交叉审查。

## 维度处理原则

不同维度的投入按题材分档，不要等量铺陈：

- **经济分两档**：
  - 经营 / 种田 / 基建 / 领主流：经济从"维度"升格为"对象"，必须重投入——产出 / 分布 / 消耗 / 枯竭曲线、债权-债务账本、脆弱度指标都要写。典型形态见西幻领主经营流：领地五要素、生产链、债权-债务可量化指标、"财富制造脆弱"机制。
  - 其他题材（都市 / 玄幻 / 言情等）：经济默认只写"主角钱包四档（穷 / 一般 / 富 / 巨富）+ 地基资源曲线"，除非剧情必需。
  - 判定标准：删掉经济设定，主角的成长弧是否还成立？成立 → 默认砍；垮了 → 重投入。
- **人文默认符号化**：只写"一两个标志风俗 + 一个禁忌"，除非题材是民俗 / 东方韵味卖点。
- **历史默认倒推式**：只留有现在消费者（主角身世、神器来历、恩怨源头）的节点，中间空白留白，需要再补。不写完整编年史。

## 结构性消费约束

每项设定必须标注它被剧情消费的时机与方式，使世界契约不是静态百科而是钩子网络：

1. **消费绑定**：每个设定项（位面 / 势力 / 规则 / 资源 / 灾厄机制）必须标注"首次被消费的圈次 / 卷"与"消费场景类型"（如扮猪吃虎起点、冤枉打脸、装逼舞台、阵营博弈）。无消费者的设定不写入。
2. **消费时序表**：产出须包含至少一张"消费时序表"（如位面 × 圈次、势力 × 圈次、神线态 × 圈次），使钩子分布可视化。表中应能看出哪些设定在第几卷首次被消费、以什么场景形态消费。

注意：消费绑定约束的是"标注消费时机"这个行为，不强制具体的 state 字段名或结构（如 `entry_tensions` / `plot_hooks`）。不同题材的世界契约结构差异极大（经营流的账本结构 vs 修仙流的境界结构），强制统一字段反而有害。关键是每项设定都能回答"它在哪、被什么剧情消费"。

## 增量扩展合法通道

当创作过程中产生 Architecture 与 Strategy 未覆盖、但剧情必需的新设定时（新势力 / 新位面 / 神国 / 深渊等），应返回 change_proposal 说明影响范围与归属层，而非自行扩张或静默忽略。

归属层判定：
- 新增 world 类设定（势力 / 规则 / 位面 / 地理）→ 归属 `world_contract`，产出新版本。
- 影响主角主线阶段或全书战略骨架的 → 归属 `strategy`，先改 strategy 再展开 world。
- 跨卷新故事线 → 归属 `story_arc`。

这条是对"只实现 Architecture 与 Strategy 实际需要的"的补充：开书时遵守该约束，中途扩展时走 change_proposal 正式通道，不得在下游输出中隐式重写上游。

## 可选方法素材

以下 expansion skill 提供题材或方法细化的可选参考，**均为可选输入，不能替代本主干产出**。主控智能体或 World Agent 可按需调用 `skill_catalog.get("<name>")` 拉取其完整 prompt 作为方法灵感：

- **scenario-atlas**（题材桥段图集）：按当前项目一级题材定位 `clusters/<题材>.md`，查阅该题材的可复用桥段、消费时序表与启发式推演提示，作为世界契约"结构性消费约束"的钩子灵感源。**不是强制拼装件**——世界契约的组织形态仍由 World Agent 按本书 Architecture/Strategy 自选。
- **world-rule-system**：当世界需要"不可打破的超自然/物理铁律"时，参考其规则边界定义方法。
- **world-growth-resource**：当世界需要"能力进阶阶梯 + 资源消耗闭环"时（修仙境界、序列魔药、异能进化等），参考其成长曲线与资源枯竭设计。
- **world-social-power**：当世界需要"势力利益博弈 + 阶层垄断"设计时，参考其势力分配与制度冲突方法。
- **world-system-interaction**：当世界存在双/多能力体系碰撞（如修真×魔法、超凡×科技）时，参考其体系翻译/压制/转化规则。

这些素材的使用条件见各自 metadata 的 `use_when` / `avoid_when`。未覆盖的题材或场景，应依靠 Architecture/Strategy 约束直接推导，不强行套用不相关素材。
