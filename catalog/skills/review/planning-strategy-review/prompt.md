# 全书战略审查 Rubric (Story Strategy Review Rubric)

审查 `strategy` 资产候选是否符合 `direction` 与 `architecture`。

## 输入边界
- 目标资产：`strategy`
- 精确上游：已锁定的 `direction` 与 `architecture`（与被审对象一并注入）

## 检查清单
1. **上游机制消费完整**：卷节奏骨架/层×卷映射/阶段收益配比/晋升-收费配对表/主导螺旋轮换表五项各有架构机制引用——静默自创节奏 = blocking。
2. **体量合规**：阶段数与 `scale` 匹配，每阶段平均 ≥ 20 万字且有字数区间；阶段空转或单阶段无曲线 = blocking。
3. **阶段目标与不可逆**：每阶段有目标状态与结束条件，结束时伴随不可逆的世界或角色状态变更——原地打转 = blocking。
4. **矛盾动力学**：核心矛盾经历奏效、反噬和不可逆代价；阶段性胜利未消解 `unresolved_claims`；终局未用 `forbidden_resolutions`。
5. **收益配比**：每个主要阶段定义明确的阶段性收益（资源/身份/能力/信息/关系/认知），与悬念配对——「只种不收」的阶段 = warning。
6. **螺旋轮换**：无单一螺旋连卷主导无蓄势 = warning。
7. **decision_points**：metadata 的决策点是命门级（2~4 个）且含完整选项结构——凑数细节 = warning，缺失且无省略声明 = blocking。

## Blocking 条件
- 违背 `direction` 或 `architecture` 约定的铁律。
- 阶段推进缺乏不可逆变化，或多阶段机械重复同一测试。
- 五项上游翻译任一缺失或静默自创。
- 全书各阶段均无阶段性收益。

## 条件审查模块（按项目组装）

频道轴的阶段收益主形态与平台耐心结构专项审查**不在本主干**——组装器按 setup 取值附加 check 模块，与上述条目同级执行。索引见 `modules/manifest.json`。

## 不得检查的下游
- 不得检查单卷细化章纲或具体场景执行卡。

## 证据要求
- 引用战略阶段节点与上游架构规则进行对照说明。
